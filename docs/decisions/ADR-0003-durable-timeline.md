# ADR-0003: Durable event storage and bounded timeline

Accepted for Phase 2, 2026-10-22. Phase 2 is explicitly authorized; the native GUI acceptance gap from Phase 1 remains open. Portable and native baseline checks passed before implementation. No recorder correctness prerequisite failed in that audit.

Use database/sql with pinned modernc.org/sqlite v1.61.0 (SQLite 3.54.1 observed in the load test). The pure-Go driver avoids adding a C compiler dependency to the sidecar. It increases Go dependency/build size; cross-build and native tests supply portability evidence, not claims of runtime support. Dependency source: [modernc SQLite documentation](https://pkg.go.dev/modernc.org/sqlite). We did not benchmark competing drivers; the portability requirement, successful existing-recorder tests and recorded load result support this choice.

Use WAL with FULL synchronous, foreign keys, trusted_schema OFF, a 1-second busy timeout and four pooled connections. SQLite documents concurrent WAL readers and a single writer, local-filesystem requirements, and FULL commit synchronization in its [WAL documentation](https://www.sqlite.org/wal.html). A process lease excludes a second engine. Writes use a nonblocking one-slot admission gate and a 5-second transaction deadline: backpressure returns STORE_BUSY instead of accumulating a queue. Reads have a 2-second deadline. The recorder treats a rejected write as capture failure and cancels through the existing sink boundary.

Schema migration 1 creates runs, events, legacy_imports and the migration checksum ledger in one transaction. Any unknown version or changed checksum refuses opening. There is no downgrade or destructive repair. Before future migrations, stop the application and copy the entire private recordings directory, including database, WAL, SHM and payloads; never copy only a live database. Automated backup and a future-schema read-only viewer are deferred, not claimed.

Run metadata and event sequence/lifecycle changes commit together. Save can update adapter version or annotate a storage interruption, but cannot manufacture completion. Event schema remains v2; optional truncation metadata is additive under the timeline-v1 capability. No distributed ordering or replay guarantee is introduced.

Payloads up to 8 KiB stay inline. Larger validated event envelopes (maximum 256 KiB) are published under payloads/SHA256.json using private temporary files, fsync, rename and directory sync before SQL references commit. These are versioned event-v2 JSON bytes, not canonical cross-language snapshot objects. Length, digest, identity and envelope are checked on retrieval. Unreferenced files after rollback/crash are retained; no automatic garbage collection or full CAS implementation. Existing journals remain untouched and are imported once per run in a transaction. Original journal tests live unchanged in the legacy package because their corruption assertions apply to that format, not SQLite.

The UI keeps one page of at most 100 summaries and loads a full event only on inspection. Indexed run/sequence and run/type/sequence queries use a cursor bound to run, filters and a captured high-water sequence. Search is a literal ASCII-case-insensitive substring over at most 1024 bytes of sanitized message + reason + upstream type; outputs/commands are detail-only. FTS and virtualization add no justified benefit to this bounded page design yet.

Startup checks SQLite integrity/foreign keys, sequence relationships, and each referenced event. It preserves damaged data, marks history damaged, and annotates unfinished runs interrupted without adding invented events or resuming a model. Full startup verification is linear in history size; the load test records its cost. Same-user malicious filesystem races, power-loss guarantees and whole-machine containment are outside the established threat boundary.
