# ADR-0004: Portable snapshots and owned materialization

Accepted for Phase 3 implementation, 2026-10-22. The user explicitly authorizes Phase 3 despite unresolved native GUI acceptance. Portable/native Phase 2 baselines passed before changes. No new framework or dependency is required.

Manifest v1 uses sorted workspace-relative slash paths. The first supported portable subset is printable ASCII; Unicode names are rejected, never normalized. Reject absolute paths, dot/traversal/empty components, backslashes, controls, Windows reserved characters/device names, trailing dot/space, components over 240 bytes and paths over 1024 bytes or 64 components. Reject case-insensitive collisions, including ancestors, and require explicit directory parents. Unicode portability awaits a normalization/collision design and actual target-filesystem tests. This intentionally restricts supported workspaces instead of silently renaming their content.

Capture regular files, including empty files, and directories including empty directories. Preserve executable status as owner mode 0700 versus 0600; directories restore 0700. Do not preserve timestamps, ownership, ACLs, xattrs, hardlink identity or sparse allocation. Hardlinks become independent byte copies; sparse files count by logical size. Skip all symlinks (internal, escaping, broken and cycles) with explicit manifest omissions, matching the existing observation policy; restore never creates links. Reject other special files. Limits: 8 MiB/file, 64 MiB included bytes, 10,000 visited entries, 2 MiB manifest, 100 configured exclusions.

Persist policy version, effective relative exclusions and omission reasons. Reuse the recorder's sensitive/dependency/build-name exclusions, add user exclusions and automatically exclude the application-data root if nested under the source. Capture is explicitly consented and blocked while the recorder is active. File bytes cannot be redacted without breaking restoration: known credential-like files are excluded, but secrets in ordinary source files can remain; no upload or encryption is added. Do not claim full secret prevention.

Capture performs two complete bounded traversals, compares file identity/size/mode/mtime around each read and compares canonical manifests across scans. This detects observed changes; it is not an atomic filesystem snapshot and cannot defeat an adversarial writer restoring prior bytes/metadata. No automatic retries conceal inconsistency. Use an idle project. Git worktrees are not required: they cannot alone preserve dirty/untracked files, and invoking Git hooks/configuration introduces avoidable behavior. Materializations are plain independent directories without .git; source HEAD/index are untouched.

Objects use SHA-256 of exact bytes, compatible with actual Phase 2 payload hashing (superseding the earlier unimplemented domain-prefixed CAS proposal). Separate objects/v1/sha256 storage contains files and canonical manifest bytes. Metadata determines role. Publish a private temporary file, set read-only owner mode, fsync, create final hardlink without replacing an existing object, remove temp, sync directory. The temporary link is solely within CAS; restored files are always independent copies. Verify complete digest/length on every read and when deduplicating. Existing corrupt objects are never overwritten.

Migration 2 adds snapshots, branches, object inventory and snapshot object references. Migration 1 text/checksum remains unchanged. preparing metadata commits first; verified file/manifest objects publish next; snapshot commit and references commit together last. Failure leaves failed metadata and possibly unreferenced immutable objects. Startup turns preparing operations failed, validates committed snapshots before use, and reports missing/corrupt objects as damaged. Prior snapshots/event history remain unchanged. No destructive GC: enumerate unreferenced and temporary objects; retain all evidence. One service admission gate serializes capture/materialization, bounded by context; the existing DB write gate remains authoritative.

Restores and branches use random generated IDs under managed-workspaces, never arbitrary destinations. Reserve a new directory exclusively, populate through os.Root, verify every restored file/directory against the manifest, sync files/directories, and only then commit ready. Failure or restart marks the operation failed and retains its partial directory for inspection; no automatic deletion or replacement. Branches reference the source snapshot and optional immutable parent branch, share CAS references, and later captures append new snapshots. A materialized workspace is mutable; edits never modify shared objects. Logical copy-on-write saves historical objects, not filesystem copy cost. No model execution, replay or sandbox claim is introduced.
